# Implementation Overview

Этот документ фиксирует фактически реализованную архитектуру Yandex Ynison для
Music Assistant 4.0.2. Это не перечень будущих фаз: незавершённые направления
вынесены в [`ROADMAP.md`](ROADMAP.md).

## Назначение и границы

Провайдер публикует Music Assistant как устройство в официальных клиентах
Яндекс Музыки. Клиент управляет сессией через Ynison, а Music Assistant получает
декодированный PCM-поток и воспроизводит его на выбранном плеере.

Провайдер не заменяет каталог Яндекс Музыки и не хранит собственные учётные
данные. Для каждого экземпляра обязателен связанный экземпляр провайдера
`yandex_music`; он служит единственным источником токена, stream details,
метаданных и radio-рекомендаций.

## Настройка и учётные данные

Setup flow в `provider/setup_flow.py` сохраняет три setup value:

- `ym_instance` — идентификатор связанного `yandex_music`;
- `mass_player_id` — целевой плеер или автоматический выбор;
- `publish_name` — имя устройства в клиентах Яндекс Музыки.

`provider/credential_source.py` читает OAuth-данные связанного провайдера, а
`provider/auth.py` проверяет и при необходимости обновляет токен через
`ya-passport-auth`. Собственные QR- и ручные сценарии авторизации удалены.
Скрытый `device_id` создаётся один раз и сохраняет идентичность устройства между
перезапусками.

Runtime-настройки позволяют разрешить ручную смену плеера и выбрать частоту и
разрядность выходного PCM. Для разных аккаунтов или опубликованных устройств
создаются отдельные экземпляры провайдера (`multi_instance: true`).

## Протокольная сессия

`provider/ynison_client.py` отвечает за две WebSocket-стадии Ynison:

1. redirector возвращает хост, ticket и session id;
2. state service регистрирует устройство и обменивается состоянием плеера.

Клиент принимает состояние очереди, активного устройства, громкости и
воспроизведения и отправляет команды управления обратно. Все отправки
сериализованы, keepalive контролируется серверными параметрами, а после
восстанавливаемых разрывов используются задержки 5, 10, 30 и 60 секунд с
jitter. Ошибки авторизации передаются провайдеру для обновления учётных данных.

## Модель Music Assistant

`YandexYnisonProvider` реализован как `PluginProvider` с возможностью
`AUDIO_SOURCE`. Каждый экземпляр возвращает один стабильный `AudioSource` с
item id `main`; его `ProviderMapping` содержит текущий заявленный PCM-формат.

Провайдер связывает события Ynison и Music Assistant в обе стороны:

- активация устройства выбирает источник на настроенном или автоматически
  найденном плеере;
- изменения трека обновляют метаданные и поток;
- play/pause, previous/next, seek и volume транслируются в Ynison;
- смена плеера разрешается только соответствующей настройкой;
- закрытие и повторное подключение не создают второй источник.

Экспериментального handoff-механизма нет: согласование выполняется через
состояние `AudioSource`, активное устройство Ynison и штатные команды Music
Assistant.

## Поток и PCM-формат

`provider/streaming.py` получает `StreamDetails` у связанного `yandex_music`,
читает поток и декодирует его средствами Music Assistant/FFmpeg. На выходе
провайдер отдаёт стерео PCM little-endian.

Базовый формат без точной подсказки трека:

- lossless: 24 bit / 44.1 kHz;
- lossy: 16 bit / 44.1 kHz.

Подсказка `StreamDetails` может поднять частоту или изменить разрядность. В
режиме `auto` частота дополнительно согласуется с возможностями целевого
плеера, чтобы объявленный `AudioSource` совпадал с фактическим потоком.
Пользовательские overrides имеют приоритет, если их значения допустимы.

## Очередь, radio и метаданные

Текущий элемент берётся из `playable_list`; stream details являются
авторитетным источником длительности и формата. Метаданные `AudioSource`
обновляются сначала из состояния Ynison, затем уточняются данными потока.

На исчерпании radio/wave-очереди провайдер сначала запрашивает синхронизацию EOV
и при необходимости получает продолжение через связанный `yandex_music`.
Обычная конечная очередь завершается без искусственного повторения последнего
трека.

## Сбои и восстановление

- временный сетевой разрыв запускает автоматическое переподключение;
- истёкший токен обновляется из связанного провайдера;
- смена учётных данных пересоздаёт сессию без смены `device_id`;
- ошибки получения или декодирования потока завершают текущую выдачу и
  передаются в журнал;
- unload отменяет фоновые задачи, закрывает WebSocket и освобождает поток.

## Проверка реализации

Модульные тесты разделены по setup flow, источнику учётных данных,
аутентификации, Ynison-клиенту, streaming и orchestration провайдера. Дополнительно
применяются Ruff, mypy, codespell, pre-commit и сборка Astro-документации.

Полная проверка зависит от согласованной версии API Music Assistant. Текущий
известный разрыв lock-файла с используемым `AudioSource` API вынесен первым
пунктом roadmap и не скрывается частичными заглушками в документации.
