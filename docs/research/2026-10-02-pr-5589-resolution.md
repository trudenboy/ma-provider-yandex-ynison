## Selected scope and acceptance criteria

reviewable, fix confirmed bugs, trim unsupported scope, and explain all resolved
threads. The provider changes must:

- Restart mixed-format PCM after the real MA selected/stream-end/unselected
  lifecycle, retaining only a matching generation-scoped restart intent.

  Keep incoming edits, repeat/shuffle, logical navigation, and RADIO replenishment.

## Verification and test adjustments

Regression boundaries are the MA AudioSource lifecycle and controls, the Ynison
WebSocket envelopes, and the native setup form. The restart regression invokes the
installed real `StreamsController._wrap_with_audio_source_lifecycle`; CDN/ffmpeg
and player I/O are replaced at external boundaries. It failed with zero restart
calls before the fix. Both rapid-control orders failed by losing one wire option.
The bridge case failed by advertising 44.1 kHz instead of the output's 96 kHz.

Existing assertions are retained except where the expected contract was wrong:
setup failure belongs to async initialization; reconfigure persistence merges old
keys and therefore requires explicit null values; arbitrary ValueError cannot be
classified as an expected callback failure. Reconnect test stop sentinels use a
transport error rather than relying on swallowing RuntimeError. Transport doubles
now support serialized mutations and physical-player resolution. The reconnect
generator test now includes the previously omitted core unselected callback.
Tests solely exercising removed, unreachable queue-edit helpers are removed with
those helpers; incoming queue fixture coverage remains. The terminal-pause assertion
now checks the same paused/progress values in the complete player-state envelope,
which makes the terminal decision atomic with repeat changes. Prefetched batch
fixtures carry their queue generation instead of permitting unscoped reuse.

Run the complete unit suite, Ruff, Mypy and all pre-commit hooks. Provider CI and
fresh review must pass before merge. Hardware playback of this follow-up is still
a human validation step; earlier Android/Station testing does not validate this
new lifecycle fix.

## Additional review observations

- Reconfigure explicitly nulls both `player` and `publish_name` as well as old auth
  fields because the core merges existing setup data.
- Available player registrations are filtered by the core selector; display/source
  clients alone cause `AbortFlow("no_players")`.
- Linked-source validation and adapter construction happen in async initialization.
- Dynamic capabilities come from `resolve_output_player()` while ownership remains
  with the user-facing player.
- Bit-depth clamping is intentionally unchanged: this core's realtime AudioSource
  PCM selector retains source precision and snaps sample rate. Encoded player output
  negotiation can clamp precision later. Applying the encoded-output rule to the
  source would create a second policy and needless format transitions.
- VERSION and the published tag already agree at 4.3.4; historical metadata
  observations do not justify changing a published tag. The follow-up release
  version is set by the maintainer after review.
